## Provisional decisions

| Decision | Why |
| --- | --- |
| Commit messages in Conventional Commits from 9 Oct, instead of "Phase N: …" | The industry standard; the MVP and the spec's phases are over |
| Local constants in PascalCase only as a suggestion (the older code uses camelCase) | Not touching 30+ places without gain; new code follows Microsoft's convention |
| Phase 1's provisional decisions stay in `docs/spike/progress.md` | Keeps this file short |
| UI text in English, like HeidiSQL; the tooltip of future items "Available in version X" | Captions taken from HeidiSQL; the spec only defines the rule |
| 27.2 items with `AvailableIn = "1.1"`; development version `0.<phase>.0` | Version 1.0 = MVP |
| Integration tests: `tests/Integration/Start-TestServer.ps1` starts XAMPP's MariaDB 10.4 on its own datadir in `%TEMP%\eunomia-it`, port 33106; CI runs them on Linux with MySQL 8.0/8.4 and MariaDB 10.6/11.4 | The only way to test against real servers without a local Docker |
| MySQL dates and times kept as text in the blocks (zero dates, fractions and TIME > 24 h exact); BIGINT UNSIGNED and DECIMAL > 18 digits too | Lossless (14.4); the server's text is what HeidiSQL shows |
| Warnings: MySqlConnector's `InfoMessage` on statements without a result; `SHOW WARNINGS` after those that return rows (the `CollectWarnings` option) | MySqlConnector does not expose the warning count of result sets |
| `AllowPublicKeyRetrieval=true`; SSL off on the session = "Preferred" TLS without verification; on = HeidiSQL's levels 0/1/2 (Required, VerifyCA, VerifyFull) | Connects like HeidiSQL to MySQL 8 servers without TLS; full verification is the default when SSL is on (23.2) |
| A missing or empty password = an empty password saved (no login prompt); "Prompt for credentials" always asks and does not save | HeidiSQL's semantics (a password missing from the registry = empty) |
| Cancelling SSL below level 2 asks for confirmation; SSL off = "Preferred" TLS | Section 23.2 |
| A minimal Data tab and Run over the primary connection (first 1,000 rows; first result set; counts in the log) | Makes the flow testable right away; phases 5 and 6 replace it |
| User queries are never repeated after reconnecting; metadata repeats once | A query may have run on the server before the connection dropped |
| The startup script runs on every connection of the session (primary, metadata, jobs) | The "replicated state" of 12.2 |
| `SessionTreeProvider` in `UI.Shell` over the `MetadataCache` (`Engine.Metadata`); state (favourites, objects seen) in `OpenSession` | The tree is a UI control; the cache and the rules stay in the engine and in App |
| Objects in natural order (numbers as numbers anywhere in the name) | The text of 4.2; HeidiSQL's `CompareAnyNode` only compares numbers at the start |
| Groups built already with the objects: the "Tables (n)" count shows straight away | The objects come in a single round trip; HeidiSQL only shows it after initialising |
| F5 reopens open databases, groups and tables and refocuses by path (transparent groups); Expand all does not open columns | Appendix D A9 asks for databases, groups and focus; columns of every table would be one query per table |

## Failures and attempts

- `CsvImportTests.CancelInServerMode` (phase 8) failed now and then with the machine under load. Cause found in phase 15: when the cancellation read by the stream wins the race against MySqlConnector's, the latter returns `MySqlException("Error during LOAD DATA LOCAL INFILE")` with the `OperationCanceledException` inside; the driver now returns it as a cancellation (`MySqlConnectionHandle.IsCancellation`, `BulkLoadCancelTests`, `CsvImportTests.CancelDuringLoadDataIsACancellationWithNoRowsSaved`).

- PR-01: this machine is now slower and noisier than on 1 Oct. The phase 1 build measures 0.67–1.19 s; phase 2's 0.8–1.2 s (a difference of ~100–150 ms, within the noise after making query tabs and menus lazy and simplifying the toolbar). No more tuning for this machine.

- `HeidiGapsTests.ExplainAutoRefreshFollowForeignKeyAndOpenUrl` failed once in a run of the whole solution (9 Oct, machine under load, without the message kept); it passed in 3 isolated runs, 2 of the headless suite and 2 of the whole solution. `RoundTripTests.OneRoundTripPerStepWhenOpeningTables` failed for the same reason (500 ms without a log line did not guarantee that the first table editor had loaded): it now waits for the real condition.

- `FindTextTests.SearchesTheTablesAndOpensTheResults` timed out once (10 Oct) waiting for the dialog's table list ("Loading tables ...") during a run of the whole solution, with the integration tests using the same server in parallel; it passed in 3 isolated runs and in 3 runs of the headless suite. If it repeats, give that wait a longer timeout or wait for the load itself.
